================================================================================
1. ACHADOS DA INVESTIGAÇÃO (antes de qualquer mudança)
================================================================================

  1. MarketTradeEvent tinha campo `source: str = "simulator"`, mas o producer
     de mercado e o Avro (market_event.avsc, já correto) sempre mandaram
     `source_system` + `produced_at`. Validar o payload real contra o modelo
     antigo descartava o valor real de source_system (sempre caía no default
     "simulator") e perdia produced_at — bug de perda de dado silenciosa,
     confirmado por leitura de código (nada ainda consome/valida essas
     mensagens em runtime — só passará a importar quando a issue #11
     (streaming) for implementada).

  2. TransactionEvent nem declarava produced_at/source_system — mesma classe
     de problema, mais branda (Pydantic v2 ignora campos extra por padrão,
     então não quebra, só descarta).

  3. .env/.env.example documentavam TRANSACTION_PRODUCER_RATE/
     MARKET_PRODUCER_RATE, mas o código sempre leu PRODUCER_RATE_TPS/
     MARKET_PRODUCER_RATE_TPS — e docker-compose.yml (serviços
     producer-transactions/producer-market) já usava os nomes certos,
     hardcoded. Ou seja: só o .env/.env.example estava desalinhado; os
     valores documentados lá nunca foram lidos por nada.

  4. Nenhum dos dois producers validava o payload contra o modelo Pydantic
     correspondente antes de publicar no Kafka — só montavam um dict cru e
     mandavam json.dumps direto.

================================================================================
2. MUDANÇAS APLICADAS
================================================================================

  - MarketTradeEvent: `source` renomeado para `source_system` (str | None),
    adicionado `produced_at` (datetime | None).
  - TransactionEvent: adicionados `produced_at` e `source_system`
    (datetime | None / str | None) — None é o caso de eventos vindos do
    batch (CSV/Bronze), que não passam pelo producer streaming.
  - TRANSACTION_SPARK_SCHEMA: adicionadas colunas produced_at TIMESTAMP,
    source_system STRING.
  - MARKET_TRADE_SPARK_SCHEMA: coluna `source` renomeada para
    `source_system`, adicionada `produced_at TIMESTAMP`.
  - kafka_producer_transactions.py: `_build_message()` agora constrói um
    TransactionEvent (valida) e retorna `model_dump(mode="json")`, em vez de
    só mesclar dicts.
  - kafka_producer_market.py: `next_tick()` voltou a gerar só o tick "puro"
    (sem metadados); nova função `_build_message()` (mesmo padrão do
    producer de transações) valida contra MarketTradeEvent e adiciona
    produced_at/source_system. `run()` atualizado pra usar `_build_message`.
  - .env / .env.example: TRANSACTION_PRODUCER_RATE -> PRODUCER_RATE_TPS,
    MARKET_PRODUCER_RATE -> MARKET_PRODUCER_RATE_TPS, adicionado
    GENERATOR_SEED (documentava só no código, faltava no .env.example).
