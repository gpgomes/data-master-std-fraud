================================================================================
CHECKLIST DE TESTES — Streaming Spark e Detecção de Fraude (issue #11)
================================================================================

Objetivo: implementar a speed layer da arquitetura Lambda — consumir
raw-transactions em tempo real, enriquecer, detectar anomalias de valor via
Z-Score numa janela deslizante por cliente, e publicar enriched-transactions/
fraud-alerts, com checkpoint e modo de replay.

Decisão de arquitetura (confirmada com o usuário): janela deslizante de
verdade, recalculada a cada micro-batch, em vez de uma baseline estática
pré-calculada. Implementação: histórico de amount/timestamp por cliente é
persistido em `s3a://silver/_stream_state/customer_amount_history/` e
recarregado a cada micro-batch (leitura-processa-grava), fornecendo o
contexto cross-micro-batch necessário para o cálculo de Z-Score — sem isso,
cada trigger de 10s veria só suas próprias poucas linhas por cliente (o
producer gera para clientes aleatórios), quase nunca o suficiente para uma
baseline.

Arquivos criados:
  - src/transformation/streaming/stream_processor.py (StreamProcessor)
  - tests/unit/test_stream_processor.py (20 testes)

Arquivos modificados:
  - src/common/schemas.py (bug real encontrado — ver seção 2)
  - pyproject.toml (per-file-ignore de ruff para o shim de compat)

Makefile: `spark-submit-stream` já existia (scaffolding do step 1.2), sem
alteração necessária — já apontava para o arquivo certo com o pacote Kafka
correto.

2. BUG REAL ENCONTRADO E CORRIGIDO — schemas.py incompatível com Python 3.8
================================================================================

Primeira execução real do job (`spark-submit ... stream_processor.py`) falhou
na importação:

  ImportError: cannot import name 'StrEnum' from 'enum'
  (/usr/lib/python3.8/enum.py)

Causa raiz: stream_processor.py é o PRIMEIRO job PySpark deste projeto a de
fato importar `src.common.schemas` (os jobs batch anteriores usavam DDLs
inline ou não precisavam de Pydantic em runtime). A imagem custom do Spark
(`apache/spark:3.5.1`) roda Python 3.8, mas schemas.py usa:
  - `from enum import StrEnum` (stdlib só a partir do Python 3.11)
  - sintaxe `X | None` nos campos Pydantic (precisa Python 3.10+; mesmo com
    `from __future__ import annotations`, o Pydantic resolve as anotações
    postergadas em runtime para construir os validators, e `X | None` como
    expressão real falha em < 3.10)

Essa incompatibilidade já existia desde a issue #8 (quando os campos
`produced_at`/`source_system` opcionais foram adicionados), mas nunca foi
detectada porque nenhum job Spark chegava a importar o módulo.

Correção em `src/common/schemas.py`:
  - Shim condicional: `if sys.version_info >= (3, 11): from enum import StrEnum
    else: class StrEnum(str, Enum): ...` (mesmo comportamento — usado com
    `model_config = {"use_enum_values": True}`, então o valor armazenado é a
    string, não a instância do enum, comportamento idêntico)
  - Todos os campos opcionais (`X | None`) trocados para `Optional[X]`
    (typing) — sintaticamente compatível com Python 3.8

`pyproject.toml`: adicionado `[tool.ruff.lint.per-file-ignores]` para
`src/common/schemas.py` (UP036/UP042/UP045) — as regras `pyupgrade` do ruff
assumem o alvo declarado do projeto (Python 3.11+) e sinalizariam o shim/
Optional como "desatualizados"; a exceção é documentada inline.

Validado dentro do container real (Python 3.8.10):
  docker compose exec spark-master python3 -c "from src.common.schemas import
  TRANSACTION_SPARK_SCHEMA, TransactionEvent, FraudAlert; ..."
  -> IMPORT OK, TransactionEvent(...) validou corretamente.

Suíte completa revalidada após a correção: sem regressão (ver seção 4).
