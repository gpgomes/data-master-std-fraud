--------------------------------------------------------------------------------
1. DECISÃO: PARQUET (NÃO DELTA LAKE)
--------------------------------------------------------------------------------

O código sempre gravou .format("parquet") em Silver/Gold, mas o Spark session
e o Makefile configuravam extensões Delta com versão incompatível com o
cluster (delta-core_2.12:2.4.0 é para Spark 3.4; o cluster roda Spark 3.5.1,
que precisaria de delta-spark_2.12:3.1.0) — Delta nunca foi de fato usado.

Decisão (validada com o usuário): manter Parquet puro. Silver/Gold são
reescritos por completo a cada execução (idempotente via overwrite dinâmico
por partição), então o log de transação ACID do Delta não agrega valor agora.
Time travel/versionamento fica para a fase de governança (roadmap 3.6).

Arquivos alterados:
  - src/common/spark_session.py — removida config de extensões/catalog Delta
  - Makefile — removidos --packages/--conf Delta dos 3 targets spark-submit-*
  - pyproject.toml — removida dependência delta-spark (não importada em lugar
    nenhum do código)
  - docs/architecture.md — "Decisões Arquiteturais" e "Componentes" atualizados

BUGS ENCONTRADOS E CORRIGIDOS (só apareceram rodando via Airflow — o
spark-submit direto contra o spark-master não os expõe, porque lá o driver
roda dentro da própria imagem do Spark, com todos os jars já presentes):

  1. Master URL sem esquema
     AIRFLOW_CONN_SPARK_DEFAULT como URI simples (spark://spark-master:7077)
     resultava em "spark-submit --master spark-master:7077" (sem "spark://").
     Causa: SparkSubmitHook._resolve_connection() monta
     master = f"{conn.host}:{conn.port}" quando conn.port existe — não
     reconstrói o esquema. Corrigido usando o formato JSON da connection
     (AIRFLOW_CONN_SPARK_DEFAULT como JSON, não URI), com host já contendo
     "spark://spark-master" — assim host:port vira "spark://spark-master:7077"
     corretamente.

  2. ClassNotFoundException: org.apache.hadoop.fs.s3a.S3AFileSystem
     O driver roda em modo client dentro do próprio container do Airflow
     (pyspark instalado via pip, sem os jars extras hadoop-aws/aws-java-sdk-
     bundle que só existem na imagem customizada do Spark). Corrigido
     adicionando packages=_S3A_PACKAGES (hadoop-aws:3.3.4 +
     aws-java-sdk-bundle:1.12.262) nas duas SparkSubmitOperator da DAG —
     resolvidos via Ivy a cada submit, mesmo padrão já usado nos outros
     spark-submit do projeto.
