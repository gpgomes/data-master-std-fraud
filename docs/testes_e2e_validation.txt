ERRATA (2026-09-23) — revisada na validação manual V1 (docs/test_status.md)
================================================================================

  Três diagnósticos deste documento estavam incorretos ou ficaram obsoletos:

  a) Limitação #3 / E2E-DAG-03 / E2E-DAG-04 ("yfinance sem dados para 2026").
     Causa real: o Yahoo Finance devolve HTTP 429 (Too Many Requests) ao IP do
     ambiente — confirmado com chamada HTTPS direta a query1.finance.yahoo.com
     de dentro do container do Airflow. O yfinance engole o 429 e devolve um
     DataFrame vazio (logs: "No timezone found, symbol may be delisted"), por
     isso o @retry do collector nunca age. Não tem relação com o relógio.
     Tratamento atual: dado de mercado é enriquecimento opcional; os gates
     bronze_market_data/silver_market_data e os assets de mercado do catálogo
     viram warning, e o bronze_to_silver pula a etapa sem derrubar o job.

  b) E2E-STR-05 / E2E-STR-06 ("0 anomalias: 10k clientes => pouco histórico").
     Causa real: o simulador de transações gerava o timestamp de cada evento
     aleatoriamente nos últimos 180 dias, e o detector usa janela de 1h em
     tempo de evento — quase nunca dois eventos do mesmo cliente caem na mesma
     hora, então fraud_score ficava sempre nulo. Corrigido: o producer carimba
     timestamp = agora. Após a correção: fraud_score preenchido e alertas reais.

  c) E2E-CAT-02 (`--strict` saía com código 1 pelos 2 assets de mercado): agora
     sai com 0 (assets `optional`, marcados com ⚠️ no docs/data_catalog.md).

BUGS ENCONTRADOS E CORRIGIDOS (PR #33)
================================================================================

  1. docker-compose.yml — healthcheck do MinIO
     test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
     A imagem minio/minio:RELEASE.2024-03-30T09-41-56Z não tem curl:
     `docker inspect minio --format='{{json .State.Health}}'` mostrava, em
     todo ciclo: "OCI runtime exec failed: exec failed: unable to start
     container process: exec: \"curl\": executable file not found in $PATH".
     O container ficava "unhealthy" pra sempre, e qualquer serviço com
     depends_on: condition: service_healthy travava — `make up` falhava com
     "dependency failed to start: container minio is unhealthy".
     Corrigido para test: ["CMD", "mc", "ready", "local"] — `mc` já vem
     embutido na imagem oficial; `docker exec minio mc ready local` retorna
     "The cluster is ready" (exit 0) sem precisar de `mc alias set` antes.

  2. Makefile — .PHONY desatualizado
     .PHONY: up down setup test lint format spark-submit-batch
             spark-submit-stream seed-data clean logs ps help
     Não incluía a maioria dos alvos adicionados depois da issue #7:
     catalog, dashboards, dashboards-export, test-unit, test-integration,
     test-cov, install, spark-submit-silver-gold, spark-submit-gold-postgres,
     producer-transactions, producer-market, api, clean-data.
     Consequência real (não só teórica): existe um diretório dashboards/ no
     repo raiz. Sem dashboards no .PHONY, o Make trata o alvo como
     correspondente a esse diretório existente e, como ele "já existe" e não
     tem timestamp mais antigo que nenhuma dependência listada, imprime
     "make: 'dashboards' is up to date." e pula a recipe inteira — o
     Superset nunca é provisionado, sem nenhum erro visível.
     Corrigido incluindo todos os 25 alvos reais do Makefile no .PHONY.

LIMITAÇÕES DE AMBIENTE (não são bugs, não corrigidas)
================================================================================

  3. yfinance sem dados reais para a data do sandbox (2026)
     ingest_market_data (Airflow) chama MarketDataCollector.collect_daily(),
     que busca cotações reais via yfinance para os últimos N dias a partir
     de "hoje". Como o relógio deste ambiente está em 2026, não existem
     cotações reais nesse período — mesma causa raiz já documentada em
     docs/test_status.md, seção Step 1.6 ("yfinance só retornou 1 registro
     real neste ambiente sandbox"). validate_bronze_data (gate GX) falha
     como consequência direta, com FileNotFoundError — comportamento
     correto do gate (falhar alto quando não há dado nenhum), não uma
     lacuna de robustez a suavizar.

  4. Great Expectations reescreve suites a cada execução
     ensure_suites() (chamado por run_gate() a cada invocação) recalcula a
     janela de freshness de bronze_transactions.json/silver_transactions.json
     relativa a datetime.now() e persiste no arquivo JSON versionado — já
     documentado em docs/runbook.md ("esses são saída, sobrescritos a cada
     run"). Confirmado nesta rodada: rodar os gates localmente deixa
     git status com esses 2 arquivos como "modified" mesmo sem nenhuma
     mudança de regra de negócio. Um commit direto pra main
     (037d68f, fora deste PR) já capturou um desses ciclos de reescrita.
