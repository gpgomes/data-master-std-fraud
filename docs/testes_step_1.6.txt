================================================================================
BUGS ENCONTRADOS E CORRIGIDOS NESTA RODADA DE TESTES
================================================================================

  1. src/common/spark_session.py
     Overwrite de partições estava no modo padrão do Spark (estático): rodar
     o job com --start-date/--end-date apagava TODAS as partições de
     silver/transactions/, não só as do intervalo processado — perda de dados
     em reprocessamentos parciais. Corrigido com
     spark.sql.sources.partitionOverwriteMode=dynamic. Revalidado: reprocessar
     4 dias específicos preservou as outras 291 partições intactas.

  2. src/ingestion/batch/transaction_loader.py (step 1.5, já em main)
     Partições diárias sem nenhuma fraude faziam o pandas inferir a coluna
     fraud_type como float64 (100% NaN) em vez de string, quebrando a leitura
     no Spark ao combinar partições com tipos físicos Parquet diferentes
     (SchemaColumnConvertNotSupportedException). Corrigido com cast explícito
     para "string" antes de gravar Parquet.

  3. docker/spark/Dockerfile (infraestrutura, não é bug de código)
     - /home/spark não existia na imagem base → Ivy não conseguia resolver
       --packages. Corrigido criando o diretório com dono correto.
     - src/ não estava no PYTHONPATH do container → ModuleNotFoundError ao
       importar módulos do projeto. Corrigido com ENV PYTHONPATH.

  4. src/common/config.py, src/common/logger.py
     A imagem oficial do Spark roda Python 3.8 (o projeto alvo é 3.11+);
     anotações como list[str] e str | None quebram o import nesse Python.
     Corrigido adicionando `from __future__ import annotations`.

  5. src/common/data_generator.py:107-109 (step 1.3, já em main — NÃO corrigido
     aqui, fora do escopo deste branch)
     cpf_masked usa formato "***.***.XXX-XX" (revela os últimos 5 dígitos do
     CPF, não 2 como a spec do 1.6 espera) e tem um espaço literal indevido
     no f-string antes do terceiro grupo, produzindo
     "***.***. 196-00" em vez de "***.***.***-00" ou "***.***.196-00".
     bronze_to_silver.py está correto (apenas repassa o valor). Recomenda-se
     tarefa separada para corrigir o gerador.
